# Changelog

All notable changes to octorepo are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/).

## [0.3.0] - Unreleased

### Added

- `--orm drizzle|prisma`: a shared `packages/db` (`@<name>/db`) with schema, first migration and
  seed, `db:migration`/`db:migrate`/`db:seed`/`db:generate` scripts, and `GET /db/health` on every
  backend. Postgres is added automatically. Docker Compose runs migrations and the seed in a
  one-shot `migrate` service before the backends start. (`db:generate` is `drizzle-kit generate`
  for Drizzle but regenerates the client for Prisma; `db:migration` creates a migration in both.)
- Services `valkey`, `rabbitmq` (with the management UI), `mailpit` and `s3` (SeaweedFS), and
  `octorepo add service <id>` to add one to an existing repo (a no-op if it is already there).
- Presets: `--preset saas` and `--preset api-platform`, also the first interactive question and
  the MCP `create` tool's `preset` input. Extra apps are appended; colliding names are rejected.
- Typed env validation: backends parse their environment with zod at startup
  (`src/generated/env.ts`, tool-owned) and exit with a message naming any missing variable.
- `AGENTS.md` in generated repos (apps, packages, services with local URLs and dev credentials,
  commands, tool-owned paths, a kbee hint), with an octorepo-managed section between markers that
  `add` refreshes, plus a `CLAUDE.md` that imports it.
- MCP tool `add_service`; `create` takes `preset`. `validate_stack` no longer requires `name`.

### Changed

- `add app` and `add service` keep the manifest's `orm` and `preset`, refresh only the
  `AGENTS.md` section, and create `CLAUDE.md` in repos that predate it. `add service` also patches
  the root `.gitignore`, `.dockerignore` and `biome.json` like `add app`.
- A `preset` key in `--config` JSON or the MCP `stack` input is ignored; use `--preset` or the MCP
  `preset` input.
- `octorepo mcp` loads the MCP SDK only when the command runs.

### Upgrading from 0.2.x

Backends generated by 0.2.x don't import `src/generated/env.ts`. `add app` and `add service`
write it into every backend, but only new backends use it. To opt an existing backend in, call
`loadEnv()` from `./generated/env.js` at the top of its entry file, as new backends do.

## [0.2.0] - Unreleased

### Added

- Backends: `fastify`, `hono` and `koa` (alongside `express` and `nest`).
- Frontends: `vue-vite` (SPA) and the SSR frameworks `nuxt`, `sveltekit`, `astro`,
  `tanstack-start`, `react-router` and `solid-start` (alongside `next` and `react-vite`).
- Shared UI packages per framework family: `ui-vue`, `ui-svelte` and `ui-solid` join `ui-react`.
  A repo gets one per family in use, and `add app` creates the package the first time a family is
  added.
- `octorepo options` lists every monorepo tool, framework and service (`--json` for machines).
- `octorepo mcp` runs an MCP server over stdio with the tools `list_options`, `validate_stack`,
  `create`, `add_app` and `read_manifest`, plus a Claude Code plugin
  (`integrations/claude-code`) that wires it up.
- SSR frameworks read `<BACKEND>_URL` at request time; pages show "unreachable" when a backend is
  down, and builds never need a backend. Every generated `/hello` call times out after 3 seconds,
  so a hanging backend shows as unreachable instead of stalling the page.

### Changed

- Generated `.gitignore`, `.dockerignore` and Biome `files.includes` also exclude the build and
  generated dirs of the new frameworks (`.nuxt`, `.output`, `.nitro`, `.data`, `.svelte-kit`,
  `.astro`, `.react-router`, `.tanstack`, `.solid`, `routeTree.gen.ts`, `apps/*/build`). The
  `.dockerignore` also excludes every `.env.*` file except `.env.example`.
- Generated `biome.json` sets `html.experimentalFullSupportEnabled`, so `.vue`, `.svelte` and
  `.astro` templates are linted and imports used only in a template are not reported as unused.
- The Next.js image runs as the non-root `node` user, and SPA images use the official non-root
  nginx image (`nginxinc/nginx-unprivileged`). Backend images already ran as non-root.
- `react-vite` shows "Backend unreachable" (was "No response") when a backend returns no data.
- Turborepo repos run `turbo run dev --concurrency=64`, so `pnpm dev` starts every persistent task
  in repos with more than 10 of them.
- Fastify backends listen on `::` (dual-stack), like the other backends.
- `add app` patches the root `.gitignore`, `.dockerignore` and `biome.json`. See "Upgrading from
  0.1.x" below.

### Upgrading from 0.1.x

Running `octorepo add app` in a repo generated by 0.1.x now patches three root files that the
generator doesn't otherwise touch. It only adds entries: user lines and values are kept.

- `.gitignore` and `.dockerignore`: missing generated lines are appended under a
  `# Added by octorepo add` comment.
- `biome.json`: missing exclusions are appended to `files.includes`, and
  `html.experimentalFullSupportEnabled: true` is set unless you already set it. If `biome.json`
  has comments, `add` leaves it unchanged and prints a warning.

If you don't run `add`, make these changes by hand before you add a 0.2.0 framework:

- `.gitignore`: add `apps/*/build`, `.nuxt`, `.output`, `.nitro`, `.data`, `.svelte-kit`,
  `.astro`, `.react-router`, `.tanstack`, `.solid` and `routeTree.gen.ts`.
- `.dockerignore`: add `**/build`, `**/.solid`, `**/.data`, `**/.output`, `**/.nuxt`, `**/.nitro`,
  `**/.svelte-kit`, `**/.astro`, `**/.react-router`, `**/.tanstack`, `**/.turbo`, `**/.env.*` and,
  last, `!**/.env.example`.
- `biome.json`: add `"!apps/*/build"`, `"!**/.nuxt"`, `"!**/.output"`, `"!**/.nitro"`,
  `"!**/.data"`, `"!**/.svelte-kit"`, `"!**/.astro"`, `"!**/.react-router"`, `"!**/.tanstack"`,
  `"!**/.solid"`, `"!**/routeTree.gen.ts"`, `"!**/.turbo"` and `"!**/.nx"` to `files.includes`, and
  set `"html": { "experimentalFullSupportEnabled": true }`.
- Turborepo: change the root `dev` script to `turbo run dev --concurrency=64` if you have more
  than 10 dev tasks. `add` does not change root scripts that already exist.

## [0.1.0]

### Added

- Initial release: `npm create @oct8/octorepo` scaffolds a pnpm monorepo (Turborepo or Nx) with
  frontends, backends, generated OpenAPI clients, shared packages, Docker images and Compose.
